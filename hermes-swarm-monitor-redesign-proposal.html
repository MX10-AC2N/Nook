Hermes · Swarm Monitor Proposition de refonte visuelle · 3 concepts

🎯 Rendre le swarm lisible par un humain

Le monitor actuel est riche en données mais exige un effort mental pour reconstruire l'état du swarm : il faut lire chaque carte, décoder les timestamps, suivre les indentations. L'objectif des 3 concepts ci-dessous est de transformer des données brutes en perception instantanée.

⚡ Tous les concepts respectent les contraintes : single HTML file, zero dépendance, CSS custom + vanilla JS, responsive mobile, appels API via /api/proxy/api/sessions?key=KEY&include_children=true.

01

📋 Kanban des Agents

👁️ coup d'œil instantané

Le principe : 3 colonnes = 3 états. Chaque agent est une carte qui « vit » dans sa colonne. On voit immédiatement qui travaille, qui attend, qui a fini — sans lire ni timer ni statut.

🎯 Avantage clé
La colonne Actif est la zone d'attention prioritaire. Un manager humain scanne la colonne de gauche et voit immédiatement la charge de travail. Les délégations en cascade sont matérialisées par des flèches entre cartes.
📱 Sur mobile
Les colonnes s'empilent verticalement (accordéon). Un filtre rapide focus permet de ne voir qu'une colonne à la fois.
⚡ Animations
Quand un agent passe de « idle » à « actif », sa carte glisse dans la colonne de gauche avec un flash. Le mouvement capte l'attention périphérique.

02

🕸️ Carte Spatiale du Swarm

🤝 relations entre agents

Une carte interactive où chaque agent est un nœud. Les liens montrent les délégations et communications. L'humain voit qui parle à qui, qui est central (hub) et qui est isolé (leaf).

🕸️ Avantage clé
Les patterns émergents sont immédiats : un nœud très connecté = un goulot d'étranglement. Un agent seul dans son coin = possiblement oublié. Les cycles de délégation sautent aux yeux.
📱 Sur mobile
La carte s'adapte au viewport. Les nœuds s'agencent en grille (forces layout simulé en CSS grid) et les connexions sont dessinées via un SVG superposé.
🔄 Animations
Les nœuds actifs « respirent » (pulse). Les délégations en cours sont matérialisées par un point lumineux qui voyage le long du lien (effet « data packet »).

03

📊 Chronologie du Swarm (Gantt)

⏱️ temporalité & enchaînements

Un diagramme de Gantt où chaque agent est une ligne horizontale. Les barres représentent la durée d'activité. Les délégations sont des flèches verticales entre lignes. On voit l'histoire du swarm en un coup d'œil — qui a lancé quoi, dans quel ordre, combien de temps ça a pris.

📈 Avantage clé
Les dépendances temporelles sont explicites : agent A a délégué à B, B a fini, puis C a commencé. On repère immédiatement les goulots (barres très longues) et les séquences sous-optimales (trous dans le flux).
📱 Sur mobile
La timeline est scrollable horizontalement. Les labels d'agents restent fixés à gauche (sticky). On peut pincher-zoomer pour voir plus ou moins de détails.
🔄 Live
La barre du présent (ligne rouge verticale) avance en temps réel. Les barres d'agents actifs s'allongent en direct.

Recommandation et prochaines étapes

la synthèse

Notre recommandation : implémenter le Kanban comme vue par défaut (le plus immédiat, le plus mobile-friendly) avec la Carte Spatiale en vue secondaire (accessible par un onglet « Relations »). Le Gantt peut être une vue optionnelle pour les sessions longues.

🎯 Priorité 1 · Vue Kanban (concept 1)
Remplacer la liste verticale actuelle par un kanban 3 colonnes. Chaque carte-agent montre : rôle, nom, preview, durée activité, mini-dots des tool calls. Les délégations sont des cartes indentées avec flèche. ~400 lignes de code réutilisables du fichier actuel.
🕸️ Priorité 2 · Vue Carte (concept 2)
Onglet supplémentaire « Relations ». Positionnement des nœuds basé sur l'arbre de délégation (pas de layout forces complexe — on utilise la hiérarchie parent→enfant comme coordonnées). SVG dynamique généré par JS. ~200 lignes de code additionnelles.
📊 Priorité 3 · Vue Gantt (concept 3)
Vue optionnelle pour les sessions longue durée. Calcul des positions des barres à partir des timestamps started_at / last_active des sessions. Ligne du présent animée. Peut venir plus tard.
🔧 Améliorations transverses (tous les concepts) :
  • Vue réelle : remplacer les tool calls synthétiques (generateToolCalls) par les vrais, via /api/proxy/api/sessions/${id}/tools
  • Notifications push : utiliser EventSource (SSE) ou un second poll plus fin pour les mises à jour sans re-rendre tout le DOM
  • Thème clair/sombre : stocker le choix dans localStorage
  • Mode « focus » : cliquer sur un agent filtre tout le dashboard pour ne montrer que lui et son sous-arbre
  • Raccourcis clavier : R rafraîchir, Esc fermer overlay
  • Export / partage : bouton « Copier l'état du swarm » (texte formaté pour coller dans Telegram/Discord)
